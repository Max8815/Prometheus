AI Boundaries

Not every workflow
needs an agent.

An agent changes how a decision gets made, not just who — or what — makes it faster. That's a meaningful upgrade for some workflows, and an expensive way to solve a problem a script already handles fine.

Take expense report review. A fixed rules check is a threshold test — over €500 needs a second signature, over €2,000 needs a director. It can't tell you why a contractor's invoice looks off even though every number technically clears policy. An agent can hold that kind of judgment — cross-referencing the vendor's billing history, the contract terms, and the pattern of past submissions before deciding whether something is routine or worth a second look. That's the gap agents are actually built to close — not speed, judgment under ambiguity.

We test every proposed use case against three questions before recommending an agent. Failing all three is a strong signal that a deterministic script will do the job for a fraction of the cost.

Does it require judgment calls?

Cases with exceptions, edge cases, or context that shifts the right answer — like deciding whether an invoice discrepancy is a typo or a real problem worth escalating.

Has the rulebook outgrown itself?

A ruleset so long and full of exceptions that changing one line risks breaking three others — like an expense policy nobody can fully explain anymore.

Is the input messy by nature?

Free-text, scanned documents, mixed formats, or anything that requires reading rather than parsing — like reconciling contracts written by five different suppliers.

BEFORE WE BUILD

We run your use case through these three questions before proposing anything. If it doesn't hold up, we'll say so and point you to the cheaper, deterministic fix instead.
